# PDQ Todo — Project Reference

## Project Overview

A modified TodoMVC (React) app with intentionally injected bugs. The app is pre-built and served from `dist/` — do not modify app source code.

## Setup

```
npm install
npx playwright install
npm run serve        # serves app on http://127.0.0.1:7002
npx playwright test  # runs all tests, outputs results.json
```

To run the full automated suite including server startup:
```
pwsh -Command ". ./Invoke-TodoTests.ps1; Invoke-TodoTests"
```

## Product Requirements

- When no todos are added, only the input textbox is visible
- Users can add a todo by typing in "What needs to be done?" and pressing Enter
- Users can have multiple items in their todo list
- Once an item is added, the footer (item count, filters, clear completed) is always visible — even if the list is empty
- Completing an item shows a green checkmark, crosses off the item, and updates the uncompleted count
- The item counter uses singular "item" for 1 item and plural "items" for multiple
- Users can complete all items using the toggle-all arrow
- Users can uncheck all items using the toggle-all arrow when all are checked
- Users can edit a todo by double-clicking and pressing Enter to save
- Users can delete a todo by hovering and clicking the X button
- Filters: All (default), Active (uncompleted only), Completed (completed only)
- Clear completed removes all completed items immediately
- Refreshing the page resets state — no persistence

## Known Bugs (filed as GitHub Issues)

1. Item counter does not update when completing or deleting todos
2. Item counter always shows "item" regardless of count (singular/plural bug)
3. Footer disappears when all todos are deleted
4. Pressing lowercase `p` in the input submits the todo prematurely
5. Submitting an empty or whitespace-only todo creates a blank list item (no input validation)

## Project Structure

```
tests/
  todo.spec.ts              # Filter and todo action test cases
  performance.spec.ts       # Performance budget test cases
  visual.spec.ts            # Visual regression, all browsers, runs in CI
  visual.spec.ts-snapshots/ # Baseline screenshots for visual regression
  helpers/
    index.ts                # Barrel export for all helpers
    fixtures.ts             # Playwright fixture extending base test with todoPage
    constants.ts            # All test constants (URL, perf budgets, todo data)
    pages/
      ToDoPage.ts           # Page object for the main todo page
    components/
      ToDoItem.ts           # Component object for individual todo items
Invoke-TodoTests.ps1        # PowerShell 7 function — full orchestration
results.json                # Generated by Playwright JSON reporter
```

## Test Architecture

- **Fixtures** (`fixtures.ts`): Extends Playwright's base `test` with a `todoPage` fixture that navigates to the app before each test. Import `{ test, expect }` from `./helpers/fixtures` instead of `@playwright/test`.
- **Page Object** (`ToDoPage`): All page-level interactions. Uses `private getItem(index)` to scope `ToDoItem` instances, enforcing Law of Demeter.
- **Component Object** (`ToDoItem`): Scoped to a single todo row's root locator. Exposes `toggleCheckItem()`, `clickDelete()`, `isCompleted()`, `hover()`, `isDeleteButtonVisible()`.
- **Barrel export** (`index.ts`): Single import point for all helper classes.

## Performance Budgets

- Initial page load ≤ 2000ms
